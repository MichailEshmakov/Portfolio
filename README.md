# Портфолио игр

Статический сайт, который берёт содержимое **прямо из гугл-таблицы**:
каждая перезагрузка страницы — свежие данные. Ни сборки, ни зависимостей,
ни файла с данными в репозитории.

Таблица: <https://docs.google.com/spreadsheets/d/1nLEEhJkWVQu3oMntNVr1hYLYvCDsXhqsOMU-S9Au9KM/edit>

## Структура

```
index.html            каркас страницы
assets/css/style.css  оформление (всё настраиваемое — в переменных сверху)
assets/js/main.js     чтение таблицы и отрисовка (настройки — в CONFIG сверху)
assets/img/           иконки и скрины игр, разложенные по годам
assets/img/images.json
                      какой игре какие файлы достались
                      (как добавить — assets/img/README.txt)
start-local-server.bat    запуск локального просмотра (двойной клик)
.nojekyll             отключает обработку Jekyll на GitHub Pages
```

## Как сайт читает таблицу

Страница — не таблица. Каждая игра это **карточка**, внутри неё строки
«название поля → значение». Названия строк берутся из шапки таблицы,
поэтому разметка подстраивается сама:

- **шапка ищется сама** — можно двигать таблицу вниз, оставлять сверху заметки
  и пустые строки;
- **колонки узнаются по названию**, а не по номеру — можно менять их местами;
- **новая колонка** сразу появляется в карточках новой строкой,
  **удалённая** — исчезает;
- строка, где заполнена одна ячейка с годом (`2025`), становится **заголовком года**;
  год можно вставить в середину, порядок берётся из таблицы;
- пустые строки и строки без названия игры пропускаются;
- ссылки в ячейках превращаются в кнопки под карточкой,
  ссылки на картинки (в том числе Google Drive) — в галерею скриншотов;
- строки над шапкой вида «подпись + ссылка» становятся кнопками в шапке сайта
  (сейчас это CV и страница разработчика на Яндексе).

Что показывается, а что нет:

| Колонка | На сайте |
|---|---|
| Игра | заголовок карточки |
| Жанр | чипсы + два фильтра («жанр» и «кроме жанра»), в каждый можно набрать несколько |
| Моя роль | чипсы + выпадающий фильтр |
| Оценка важности | **не показывается**, но задаёт ползунок и сортировку. Пусто — считается 2 |
| Тэги, 2д/3д | **не показываются**, но участвуют в поиске |
| Технологии | спрятаны, показываются кнопкой «Технологии» в панели |
| Поиграть, Скрины | кнопки и картинки |
| — | иконка игры в шапке карточки берётся не из таблицы, а из `assets/img/images.json` |
| Остальные | обычные строки карточки |

Панель фильтров:

- **Поиск** — по **всем** полям сразу, включая спрятанные; несколько слов
  через пробел ищутся вместе;
- **Жанр** и **Кроме жанра** — оставить нужные жанры или, наоборот, убрать
  их из выдачи (например, казуальные игры). В каждый фильтр можно набрать
  несколько жанров: выбранное уходит из списка и появляется чипсой под ним,
  клик по чипсе снимает выбор. Несколько жанров в «Жанре» — это «или»:
  игре достаточно попасть в любой из них; в «Кроме жанра» — наоборот, игра
  уходит, если у неё есть хоть один из отброшенных жанров;
- **Роль** — оставить проекты с нужной ролью;
- **Важность от** — ползунок: игры с оценкой ниже порога не показываются.
  По умолчанию 1. Шкала берётся из таблицы: максимум ползунка — самая высокая
  оценка в ней. Игра без оценки считается игрой с важностью 2 —
  и в фильтре, и в сортировке (`scoreWhenMissing` в `CONFIG`);
- **Сортировка** — «сначала дата, потом важность» (по умолчанию: блоки по годам,
  внутри года важное выше) или «сначала важность, потом дата» (блоки по оценке,
  внутри блока порядок таблицы).

## Картинки: иконки и скриншоты

Картинки берутся из двух мест сразу — из папки сайта и из колонки «Скрины».

### Папка сайта

В `assets/img/` лежат иконки и скрины, разложенные по годам, а рядом
`images.json` — список вида «название игры → иконка и скрины». Статическая
страница не умеет читать содержимое папки, поэтому список ведётся файлом.

- **иконка** показывается маленьким квадратом слева от названия в карточке;
- **скрины** попадают в галерею под шапкой карточки.

Ключ в `images.json` — название игры ровно как в колонке «Игра»; регистр, ё/е
и лишние пробелы не важны, а если название в таблице подрежут до первой точки
или двоеточия, картинки всё равно найдутся. Файла нет или он сломан — сайт
просто работает без этих картинок. Подробности и пример — в
`assets/img/README.txt`.

Папки с годами внутри `assets/img/` нужны только для порядка: год игры сайт
берёт из таблицы, поэтому файл может лежать в папке `2014`, а игра стоять
в таблице 2013 годом.

### Колонка «Скрины»

Колонка «Скрины» понимает два вида записи, их можно смешивать в одной ячейке
через запятую:

1. **Имя файла из папки `assets/img/`** — например `arena-1.png`. Файл лежит
   рядом с сайтом, грузится быстро и ни от кого не зависит.
2. **Ссылка на картинку** — прямой адрес с расширением, файл на Google Диске
   (ссылка «Открыть доступ по ссылке»), imgur. Всё остальное сайт тоже пробует
   показать картинкой; не получилось — на её месте будет обычная ссылка.

**Картинку, вставленную прямо в ячейку** (Вставка → Изображение в ячейке или
формула `=IMAGE()`), сайт увидеть не может: Google-таблица не отдаёт такие
картинки в выгрузке CSV — в выгрузке ячейка пустая. Такой скрин нужно положить
в `assets/img/` и написать в ячейке его имя либо заменить ссылкой на файл.

Поиск, фильтры и сортировка записываются в адрес страницы — такой ссылкой
можно поделиться.

## Что и где менять

Почти всё живёт в объекте `CONFIG` в начале `assets/js/main.js`:

- `sheetId` / `gid` — другая таблица или лист;
- `columns` — синонимы названий колонок (переименовал колонку в таблице —
  допиши сюда, и сайт снова её узнает);
- `hiddenFields` — что не показывать совсем (сейчас: важность, 2д/3д, тэги);
- `collapsedFields` — что прятать под кнопку (сейчас: технологии);
- `chipFields` — что рисовать чипсами;
- `filterField` — из какой колонки собирается список фильтра;
- `minScoreDefault` — где стоит ползунок важности при открытии страницы;
- `scoreWhenMissing` — какой важностью считать игру без оценки (сейчас 2);
- `sortDefault` — порядок по умолчанию (`date` или `score`);
- `imageDir` — папка с картинками (сейчас `assets/img/`);
- `imagesFile` — список «игра → иконка и скрины» (сейчас `assets/img/images.json`);
- `fixedLinks` — ссылки, которых нет в таблице (Telegram).

Внешний вид — переменные в начале `assets/css/style.css`: цвета, ширина
страницы, скругления, ширина колонки с названиями полей. Тёмная и светлая
темы переключаются кнопкой в углу, выбор запоминается.

## Доступ к таблице

У таблицы должен быть доступ **«Все, у кого есть ссылка» → «Читатель»**.
Иначе сайт покажет ошибку и предложит открыть таблицу. Если таблица временно
недоступна, показываются последние удачно загруженные данные из браузера.

## Локальный просмотр

**Двойной клик по `index.html` не работает** — открытую как файл страницу браузер
не пускает к гуглу, и вместо игр будет ошибка «Failed to fetch». Доступ к таблице
тут ни при чём. Нужен веб-адрес: опубликованный сайт или локальный сервер.

Проще всего — двойной клик по `start-local-server.bat`: он поднимет сервер и
откроет <http://localhost:8000/>. То же самое вручную:

```bash
python -m http.server 8000
```

## Публикация на GitHub Pages

1. Запушить папку в ветку `main`.
2. Settings → Pages → Source: **Deploy from a branch**, ветка `main`, папка `/ (root)`.

Все пути относительные, поэтому сайт работает и в подпапке репозитория,
и на корневом домене.
